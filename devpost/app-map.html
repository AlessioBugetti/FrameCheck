FrameCheck · Technical reference

From a suspicious interval to a decision

A local video review workspace: analyze the original, inspect candidate Black frames, Frozen frames and Silence in context, record human decisions, and export an offline HTML report.

The main pieces

1. Load one video

framecheck/server.py
upload / demo

Stream a bounded file into an app-owned temporary job directory. Validate contents, codecs and timing.

2. Analyze the original

framecheck/media.py
analyze

Native FFmpeg checks the original. A compatible preview is prepared separately when needed.

3. Review in context

frontend/src/App.tsx
selectFinding / classify

Pause, seek, inspect and decide. Review decisions live only in React memory for this session.

4. Export all decisions

frontend/src/report.ts
createReport

A standalone HTML file includes all findings, actual settings, decisions and playback status.

The Python backend has one current job. Temporary original/preview files are cleaned on explicit reset or normal shutdown; crashes can leave files behind. There is no database, external AI service or cloud storage.

A three-stop reference route

Open the files below and search for the named symbols to follow the original-to-preview review path.

  1. Keep detection and playback separate

    framecheck/jobs.py → JobManager.process
    framecheck/media.py → analyze / make_preview

    Analysis reads job.original. Preview generation also reads the original and writes a separate file. A failed preview changes the preview phase while successful findings stay available; it never makes a finding Problematic automatically.

  2. Keep a common timeline

    framecheck/media.py → ffmpeg_input / inspect_media

    Both media paths use -copyts -start_at_zero. Packet presentation ends establish duration, and -fps_mode vfr preserves variable timing in the preview. Output duration must agree within 0.10 seconds; browser landmarks test frame correspondence as well.

  3. Make selection visible and deliberate

    frontend/src/App.tsx → selectFinding
    frontend/src/review.ts → contextStart / nextUnreviewed

    Selecting a finding pauses and seeks to max(0, start - 1). The same selected ID highlights the list and timeline. Decisions do not advance; Next unreviewed applies active filters, searches forward and wraps. If classification removes selection, playback pauses without seeking.

Follow the verification evidence

tests/test_media.py → test_shared_offset_variable_rate_and_delayed_audio checks difficult source timing. frontend/e2e/performance.spec.ts compares real decoded original/preview frames at 1, 149.8 and 298.8 seconds. frontend/e2e/review.spec.ts verifies selection, decisions, filter removal and explicit continuation.

A practice to reuse

Turn a technical uncertainty into an observable contract. The approved specification required original/preview timestamp correspondence within 0.10 seconds. The application uses common normalization, checks duration, and then tests actual browser frames at start, middle and end.

On the 482.8 MB, nearly five-minute synthetic workload, maximum observed original/preview frame-time difference was 0.025065 seconds. See devpost/validation/slice-4/browser-performance.json and frontend/e2e/performance.spec.ts. Matching durations alone would not establish matching content.

On another project, define the visible result and tolerance first, choose a concrete example that can disprove the assumption, then test through the real user path. Keep the claim bounded by the evidence: these results do not establish every codec, resolution, browser or real recording.

Run the app again

From the repository root, after installing the dependencies described in README.md:

npm --prefix frontend run build
.venv/bin/python -m uvicorn framecheck.server:app --host 127.0.0.1 --port 8765 --workers 1

Open http://127.0.0.1:8765/ in Chrome and choose Try the demo. Export before reloading if you want to retain your decisions. The app accepts the documented MP4/MOV/MKV/WebM combinations up to five minutes and 500 MB.

Recheck the core behavior
.venv/bin/python -m unittest discover -s tests -v
npm --prefix frontend test -- --run
npm --prefix frontend run test:e2e

Browser tests reserve isolated port 8766. Large-fixture performance validation is documented in README.md; it is not part of the ordinary test run.
